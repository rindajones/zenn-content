# はじめに

[前回](https://zenn.dev/rindajones/articles/variable-target-env)は、可変目標Yaw制御と低出力制御のための強化学習環境を構築しました。

今回使用するアルゴリズムは、これまでと同じSAC（Soft Actor-Critic）です。

学習対象は、

```text
-90° ～ +90°
```

の5°刻み、合計37目標です。

最初は、

```text
±5°
↓
±10°
↓
±15°
↓
...
↓
±90°
```

のように、小さな目標角から順番に学習範囲を広げる**カリキュラム学習**を採用しました。しかし、学習を続けるうちに、すでに成功していた角度で再び失敗する問題が現れました。

さらに、推論結果を繰り返し目視確認している中で、

> **そもそも小さい目標角ほど簡単なのか？**

という疑問を持つようになりました。

最終的にはカリキュラム学習をやめ、37目標すべてを最初から学習する `full_range` 方式へ変更しました。

今回は、その試行錯誤も含めて紹介します。

# 最初はカリキュラム学習を試した

最初の考え方は単純でした。

```text
小さい目標角
↓
大きい目標角
```

と段階的に学習すれば、いきなり広い範囲を扱うより学習しやすいのではないかと考えました。実際に、

```text
±5°
±10°
±15°
±20°
...
```

とステージを進め、学習範囲を広げることはできました。

ある実験では、

| Stage | 範囲 | 通過step |
| ---: | ---: | ---: |
| 1 | ±5° | 74,100 |
| 2 | ±10° | 150,100 |
| 3 | ±15° | 214,700 |
| 4 | ±20° | 279,300 |
| 5 | ±25° | 343,900 |
| 6 | ±30° | 469,300 |
| 7 | ±35° | 537,700 |
| 8 | ±40° | 602,300 |
| 9 | ±45° | 718,200 |

まで進みました。

一見すると、カリキュラムは機能しているように見えます。

# 新しい角度を覚えると、以前の角度で失敗する

しかし、学習範囲を広げていくと別の問題が現れました。

大きな目標角では成功している一方で、

```text
+10°
+15°
+20°
```

など、すでに学習した小さな目標角で失敗することがありました。

Replay Bufferを見ると、ステージが進むにつれて小角度の経験が相対的に少なくなっていました。そこで、Replay Bufferの遷移を目標角ごとに管理し、ミニバッチ内で各目標角の経験ができるだけ均等になるように変更しました。

つまり、

> **新しい目標角を学習しても、以前の目標角の経験が埋もれない**

ようにしました。

# Actorが出した指令と、環境へ適用される指令をそろえる

もう一つの問題は、`Actor` が学習している行動と、環境へ実際に適用される行動の違いでした。

環境側では、

```text
Command Envelope
Command Rate Limit
```

によってYaw指令を制限しています。

一方、`Actor` / `Critic`の更新では、制限前のRaw指令をそのまま評価していました。そこで `Actor` / `Critic` 側にも環境と同じProjectionを適用し、

```text
Actorが要求した指令
↓
環境と同じ制約を適用
↓
Criticで評価
```

という構成にしました。

例えば、環境側の制約によって最大0.3しか適用できない状態で、`Actor` が1.0を要求しても、実際の制御には0.3しか使用されません。そこで、Raw指令と実際に適用可能な指令の差にもコストを与え、環境側で制限されることを前提に過大な指令を出し続けることを抑えました。


# それでも残った疑問

カリキュラムを成立させるために、Replay Samplingや行動Projectionなどの対策を加えました。

しかし、推論結果を目視確認していると、別の疑問が残りました。

> **5°は本当に90°より簡単なのか？**

カリキュラム学習では、

```text
小さい目標角 = 簡単
大きい目標角 = 難しい
```

という順序を、暗黙的に置いていました。

推論結果をBlenderで目視確認していると、小さい目標角だからといって、必ずしも制御が容易とは言えないように感じました。例えば5°では、

```text
少し旋回
↓
すぐに減速
↓
小さな角度で安定
```

させる必要があります。

一方90°では、目標までの距離が大きいため、旋回初期には大きな出力を使う余地があります。吊り荷の種類や慣性によっても挙動は変わります。

そのため、

> **目標角の大きさと制御難易度を同じものとして扱う必要はない**

と考えるようになりました。

# カリキュラム学習をやめる

そこで、カリキュラム学習そのものをやめました。

目標角の大きさによって、

```text
5°は簡単
90°は難しい
```

という難易度をあらかじめ設定せず、最初から37目標すべてを同じ学習対象として扱うことにしました。

# 結果的に、一般的なMLの学習に近くなった

この方法は、最初から意図していたわけではありませんが、結果的に一般的な機械学習の学習方法に近いものになりました。

例えば画像認識では、通常、

```text
簡単な画像だけ学習
↓
少し難しい画像
↓
難しい画像
```

と必ずしも順番に学習するわけではありません。

学習対象となるデータ分布全体からサンプルして学習します。今回も、

> **最初から対象とする目標Yaw角全体を学習させる**

という考え方になりました。

もちろん画像認識と強化学習では学習方法そのものは異なりますが、対象範囲に人為的な難易度順を設けず、対象分布全体から学習するという点では、考え方が近いと感じました。個人的にも、こちらの方が

> **1つのモデルで任意の目標Yaw角へ制御する**

という今回の目的に対して自然に感じました。

# 目標角を3つの範囲に分けてサンプリングする

37目標を単純に一様サンプリングすると、目標数の多い角度範囲ほど選択される回数も増えます。そこで、小角度・中角度・大角度という制御特性の異なる領域を均等に経験させるため、3つの角度層を先に選ぶ方式としました。

```text
0° ～ 20°
20° ～ 60°
60° ～ 90°
```

学習エピソードでは、

1. 3つの角度範囲を均等に選ぶ
2. 選ばれた範囲内の目標角を均等に選ぶ

という方法を使用します。

コードでは概ね次のような処理です。

```python
def sample(self):
    targets = random.choice(self.targets_by_stratum)
    return float(random.choice(targets))
```

Replay Bufferからのサンプリングも同様に、

```text
角度範囲を均等
↓
範囲内の目標角も均等
```

となるようにしました。

これにより、小角度・中角度・大角度のいずれかへ経験が偏ることを抑えます。


# deterministic evaluationを分ける

学習中の `Actor` は探索を含むため、同じ方策でも成功率は探索ノイズの影響を受けます。そのため、学習中の成功率だけを見て、

> **このモデルは37目標を安定して制御できる**

とは判断できません。そこで、学習中の評価と、モデルを採用するための評価を分けました。

```text
学習中
→ physical_success の移動平均を見る

定期評価
→ 探索なしのdeterministic evaluation
→ 37目標を個別に評価
→ physical_success と quality_success の両方を見る
```
学習中の評価は、学習が進んでいるかを見るために使用します。

一方、定期評価では探索を止め、同じ条件で37目標を評価します。最終的にどのモデルを残すかは、こちらの結果を基準に判断します。

# bestモデルは「最後のモデル」ではない

SACでは学習 `step` を増やせば、必ず方策が良くなるわけではありませんでした。そのため、`10,000 step` ごとのdeterministic evaluationを使って `best Actor` を保存します。

full range学習では、まず、

1. `quality_success` が高い
2. `physical_success` が高い

ことを優先します。

成功率が同じ場合には、

- 小角度での `hold` 出力
- 小角度でのRaw平均出力
- 全体の `hold` 出力
- 各角度層のRawピーク
- 全体のRaw平均
- 指令変化
- 最終誤差

などを比較します。つまり、

> **低出力だからbest**

ではなく、

> **まず成功し、その中でより低出力なモデルをbest**

としました。

:::message
なお、これは今回の制御目的に合わせて設定した選択基準であり、`best Actor` の評価方法そのものにも検討の余地があります。
:::

# 学習を安定させるための調整

`full range` 学習へ変更した後も、方策が評価ごとに変動する問題は残りました。

そこで最終的な学習では、

```text
Actor learning rate      = 1.0e-4
Critic learning rate     = 3.0e-4
Batch size               = 512
Actor update interval    = 2
alpha                    = 0.03
```

としました。

また、

- 成功領域でRaw指令と適用指令を抑える
- `Actor` の大きなRaw要求へ `L2/L4` コストを与える
- `Actor` の更新をCriticより遅くする
- `Batch size` を増やして更新ノイズを下げる

といった調整も行っています。

全37目標で `quality_success` を達成した後は、

```text
alpha = 0.03 → 0.01
```

へ変更し、探索による方策変動を小さくします。

# H鋼で全37目標に成功

H鋼を使って `full range` 学習を行ったところ、`550,000 step` で初めて37目標すべてについて、

```text
physical_success = 1.00
quality_success  = 1.00
```

を達成しました。

このとき、

```text
final payload error = 2.3°
act_abs             = 0.048
```

でした。つまり、

> **1つのモデルで-90°～+90°の37目標を扱いながら、低出力条件も同時に満たす**

ことができました。

# 100%成功しても、その後また崩れる

ただし、ここで学習が終わったわけではありません。

評価はその後、

```text
550k : 1.00
560k : 0.81
600k : 0.92
650k : 0.95
660k : 1.00
```

と変動しました。

学習中は `10,000 step` ごとにdeterministic evaluationを行い、全37目標に成功した `Actor` はチェックポイントとして保存しました。また、評価結果がそれまでのbestを上回った場合には、`best Actor` を別途更新して保存しました。

H鋼では `660,000 step` の `Actor` が、

```text
physical_success = 1.00
quality_success  = 1.00
act_abs          = 0.048
```

でbestとなりました。この経験からも、

> **学習を長く続けたモデル = 最も良いモデル**

とは限らないことが分かりました。

# 今回のまとめ

今回は、可変目標Yaw制御モデルの学習方法について紹介しました。

最初は、

```text
小さい目標角
↓
大きい目標角
```

というカリキュラム学習を採用しました。

しかし、

- 新しい角度を学習すると既習角度で失敗する
- Replay Buffer内で経験の偏りが生じる
- ActorのRaw指令と環境へ適用される指令に差がある
- 推論を目視すると、小さい目標角ほど簡単とは限らない

という問題や疑問が出てきました。最終的には、

> **目標角に人為的な難易度を設定せず、最初から全範囲を学習する**

方法へ変更しました。そして、

```text
-90° ～ +90°
5°刻み
37目標
```

を1つのモデルで学習し、H鋼では全37目標について `physical_success` と `quality_success` の両方を満たすモデルを得ることができました。

また、学習後半で方策が再び悪化することもあったため、最終 `Actor` ではなくdeterministic evaluationによるbest Actorを採用する方式にしました。

次回は、この学習方法をH鋼、平板、トラスの3種類の吊り荷へ適用し、代表的な目標Yaw角で制御結果を確認します。
